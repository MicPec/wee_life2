# Agent notes for wee-life2

## Commands

- Run the simulation: `uv run wee-life2`
- Run with custom size: `uv run wee-life2 --width 800 --height 600`
- Headless smoke test: `SDL_VIDEODRIVER=dummy timeout 10 uv run wee-life2`
- Compile check: `uv run python -m compileall src`
- Run test suite: `uv run python -m unittest discover tests`
- Genetics/energy-budget tests only: `uv run python -m unittest tests.test_genetics`
- Steering-direction / heal-tile tests only: `uv run python -m unittest tests.test_steering`
- Tests that build a bare `Organism` and exercise a sensory gene must pin `organism.angle` — `Organism.__init__` randomises it, so a single-ray sensor (`terrain_rays=1`) fires in a random direction and the test is flaky (this bit `test_scent_publishes_perception_event`)
- Headless balance test: `SDL_VIDEODRIVER=dummy uv run python -c "from wee_life2.simulation import Simulation; s=Simulation(); ..."`
- Open map editor: `uv run wee-life2 --edit-map`
- Use custom map file: `uv run wee-life2 --map-file my_map.json`
- Run a sample map: `uv run wee-life2 --map-file maps/maze.json` (also `maps/islands.json`, `maps/arena.json`, `maps/corridors.json`, `maps/quadrants.json`)
- Generic config override: `uv run wee-life2 --set KEY=VALUE` (repeatable; any `core/config.py` constant, e.g. `--set MATING_RATE=0.3 --set RADIATION_DAMAGE=0.5`), value is cast to match the existing constant's type (bool/int/float/str); errors out on an unknown key. Invalid values raise `SystemExit` with a readable message instead of leaking a `ValueError` traceback, and bool values only accept `1/true/yes/on` / `0/false/no/off` — an unrecognised token is an error, it no longer silently coerces to `False` (so `--set GRAY_WITH_AGE=banana` used to quietly disable the flag)
- `--no-stats` is applied *after* `--config-file` and `--set`, so an explicit `--no-stats` always wins over `STATS_ENABLED: true` coming from a preset
- Generic config inspection: `uv run wee-life2 --get KEY` (repeatable; prints current value(s) and exits without launching the sim/editor)
- Load config from JSON: `uv run wee-life2 --config-file my_config.json` (flat JSON dict of all public `core/config.py` constants; loaded before `--set`, so `--set` can override values from the file)
- Open config editor: `uv run wee-life2 --edit-config` (Textual TUI for editing and saving JSON presets; `wee-life2 --config-file my_config.json --edit-config` opens that file)
- The old per-option flags (`--radioactive-damage`, `--lava-damage`, `--food-on-death-chance`, `--mating-rate`, `--asexual-cooldown-multiplier`) were removed in favor of the generic `--set`/`--get` system in `main.py` (`_apply_config_overrides`/`_print_config_values`)
- In-simulation controls: `ESC` quit, `H` toggle help, `L` toggle legend, `SPACE` pause, `LMB` spawn, `RMB` remove, `R` spawn random organisms, `E` toggle map edit mode
- In edit mode: `0-5` select tool, `LMB` draw, `RMB` erase, `S` save, `C` clear, `R` randomize, `E` exit, `ESC` quit
- Hover an organism while paused to see its DNA/stats panel
- **Steering sign convention (`Organism.add_drive(angle_delta, weight)`)**: `angle_delta` is always the angle *toward* the point of interest, and the sign of `weight` decides attraction (`+`) vs repulsion (`-`) — `combined_drive()` sums `cos/sin(angle + delta) * weight`, so a negative weight already reverses the vector. Reversing the angle (`+ math.pi`) *and* passing a negative weight cancels out and produces the exact opposite behaviour. This bug was live in `fear` (fled straight into threats), in `memory`'s hazard/wall branches (navigated into remembered lava/walls) and in the `steer_away()` helper; the `memory` water branch was the one correct reference. Repulsive genes keep their negative `*_weight` defaults (`fear.danger_weight`, `memory.hazard_weight`/`wall_weight`) and must pass the un-reversed `to_angle`. Regression tests: `tests/test_steering.py` plus `test_memory_wall_recall_steers_away`/`test_memory_hazard_recall_steers_away`. When testing a steering gene, always assert the resulting *heading* (`organism.combined_drive()`), never just that a drive exists — two earlier tests asserted the inverted heading and locked the bug in
- `eye`/`scent` pick ONE best target by maximising a score, so a repulsive candidate (negative `threat_weight`/`danger_weight`) must be RANKED on `abs(weight)` and carry its sign only at `add_drive` time — ranking on the signed value makes the *farthest* threat win (score rises toward 0 with distance) and lets any positive food/mate score suppress the threat response entirely. `fear.py` is the correct reference; regression tests: `TestSenseThreatSelection` in `tests/test_steering.py`
- `touch` gene now detects and steers away from walls and environmental hazards (radioactive and lava tiles); `World.is_hazard()` is the generic hook for future hazard types. It also treats water as a hazard for organisms lacking the `amphibious` gene (checked via `organism.dna.genes`, not the per-tick phenotype flag, so it works regardless of gene order)
- `memory` gene consumes `PerceptionEvent`s from `eye`/`scent`/`touch`, remembers interesting tiles, and recalls them as steering hints. If an organism has several `memory` genes, only the first one runs the logic, but their parameters are aggregated (`capacity`/`ray_count` sum, `retention`/`perception_range`/`recall_range` max, `*_weight` sum). Recall ignores memories more than ~126° behind the organism and caps the combined weight at 0.5, so memory nudges rather than dominates.
- Map editor tools: `0` empty, `1` wall, `2` radioactive, `3` lava, `4` water, `5` heal
- Map generation (`R` in either editor, or no saved map) lives in `core/map_generator.py:generate_terrain` and is reached via `TileMap.generate_map(seed=None, *, water_fraction=..., wall_fraction=..., hazard_fraction=..., heal_fraction=...)`; the old per-tile `wall_rate`/`water_rate` scatter generator is gone. It floods the lowest tiles of a domain-warped Perlin fBm height field, smooths the coast, dissolves specks, then corrects the water count along the shore so the share is exact (drawn from `MAP_WATER_FRACTION_MIN..MAX`, 35–40%). Walls are one-tile-thick lines, not blobs. `SHORE_WALL_SHARE` (~70%) of the wall budget goes to `_draw_shore_walls`: the outline of the land within `SHORE_WALL_DISTANCE` (octile distance via `_octile_distance` — chessboard rings square off) of the water — at the default 1 that is every land tile touching the water, so walls sit right on the shore (3–4 would leave a corridor between wall and water) — with junctions where two lakes' outlines meet cut out (they double up into 2x2 lumps), ordered end-to-end by `_walk_path` and cut into `SHORE_WALL_LENGTH` walls separated by `WALL_DOOR_WIDTH` doorways, longest first. The remainder goes to `_draw_wall_lines`: contour strokes, straight strokes with up to two bends, and `WALL_CORRIDOR_SHARE` parallel pairs. All strokes are 4-connected staircases (`_line_cells`/`_close_diagonals` — corner-touching walls leave a slit), are cut where they curl back alongside themselves (`_trim_self_contact`), may touch other walls at no more than `WALL_MAX_CONTACT` cells and wall only land (a wall over water would eat the exact water share). `_connect_pockets` carves a 0-1-BFS path out of any walled-in pocket and widens it along the wall to a three-tile doorway (invariant: all non-wall tiles are one 4-connected region). Hazards and heal come as `HAZARD_ISLANDS`/`HEAL_ISLANDS` (2–3) compact islands, planned up front by `_plan_islands` as `(tile, medium, size)` and grown by `_scatter_islands`/`_best_island`: one lava island on land against a wall's landward side, the rest radioactive; the first non-lava island of each group (and later ones with the water share as probability) goes out on a lake, on open water with a tile of water around it. Water islands replace water, so `generate_terrain` floods `water_target + reserve` up front and calls `_match_water_count` at the end (a water island that found no lake falls back to land and its reserve is drained off the coast). Land hazards keep `HAZARD_SHORE_GAP` (chessboard) off the water so they never plug a doorway in a coastal wall. A heal/hazard tile on a lake is not `TILE_WATER`: amphibians on it pay `AMPHIBIOUS_LAND_DRAIN` and are pulled off it by their water drive, non-amphibians do not drown on it; seeds keep a third of the board apart (spacing beats roundness when the board is crowded), need a mostly open square around them (`_roomy`, summed-area table) and each island gets `ISLAND_SEED_TRIES` attempts scored by `_island_quality` (size x compactness) so none grows as a strip along a corridor; heal oases keep `HEAL_HAZARD_GAP` from hazards. `None` fractions read `config.MAP_*` at call time so `--set` works; an unseeded call draws its seed from the global `random`, so `random.seed()` keeps maps reproducible. The grid is rewritten in place (`row[:] = ...`). Generated boards (and `clear_map`, `C`) have no wall frame — the board edge already stops organisms (`Organism` clamps to world bounds, `tile_at` returns wall off the board). Internally `generate_terrain` works on the board padded with a one-tile ring of wall and crops it at the end, because the internal helpers (`_components`, `_connect_pockets`, `_touches`, ...) rely on that ring for bounds and the ring tells them the truth about the edge; call them only on a padded grid (tests use a `padded()` helper). Tests: `tests/test_map_generator.py`
- `Organism._apply_hazards_and_water()` treats three concerns as *independent* (not one `elif` chain): hazard damage (radioactive/lava, mutually exclusive by tile), wrong-medium drain (`WATER_DROWN_DAMAGE` vs `AMPHIBIOUS_LAND_DRAIN`), and heal tiles. Chaining them let the amphibious land-drain branch swallow the heal branch, so `amphibious` organisms could never benefit from a heal tile (regression test: `test_amphibious_also_heals_on_heal_tile`)
- Water tiles (`World.TILE_WATER`, `World.is_water()`) are walkable but not a hazard: organisms without the `amphibious` gene get `config.WATER_SPEED_PENALTY` velocity and `config.WATER_DROWN_DAMAGE` energy drain per tick; `amphibious` gene organisms move at full speed and regen energy while swimming
- `eye`/`scent` share the distance-sense machinery in `genes/sensing.py`: `sight_discount()` (the water/hazard line-of-sight multiplier below), `terrain_drive()` (the fan-of-rays loop that publishes `PerceptionEvent`s and folds hits into ONE aggregated "terrain" drive so multiple walls don't make the organism spin), and `fan_ray_angles()`/`radial_ray_angles()` (eye sweeps its FOV, scent sweeps a full circle). Only the ray layout and sharpness factor differ — `eye` weights by `acuity`, `scent` by `precision` and additionally smells heal tiles (`heal_weight`/`heal_threshold`, only while hurt). Target scanning (food/mate/threat) stays in each gene — the FOV check, pheromones, poison discrimination and danger thresholds are genuinely different. Note: a `fan_ray_angles` fan of 1 ray fires at the view *centre*; the pre-refactor code fired it at `view_angle - fov/2` (deliberate micro-fix, deterministic fingerprint unchanged)
- `eye`/`scent` genes discount (multiply steering weight by `config.WATER_SIGHT_DISCOUNT`, stacking if both apply) any food/mate target whose line of sight/smell crosses water (`World.line_crosses_water()`, skipped for `amphibious` organisms via `organism.dna.genes`, not the phenotype flag) or a radioactive/lava tile (`World.line_crosses_hazard()`, applies to all organisms)
- `eye`/`scent` only generate a food-seeking drive if the organism has a `metabolism` gene (checked via `organism.dna.genes`); without it, food is invisible to those senses (mate/threat detection unaffected)
- `herd` gene: attracts organisms toward others sharing the same `organism.name` (species label); `amphibious` gene: safe/full-speed water movement
- `amphibious` water-return drive: on land the first `amphibious` gene steers toward `World.nearest_water` with weight `water_weight * (base_pull + (1 - base_pull) * urgency)`, urgency ramping 0->1 as energy falls below `urgency_threshold`. It fires even when well-fed (`AMPHIBIOUS_LAND_DRAIN` kills a full amphibian in ~25 s) and needs no `eye`/`scent` — an earlier eye/scent gate and a 50%-energy cutoff let most amphibians wander inland and die. The nearest-water lookup is cached per gene instance for `RETARGET_TICKS` (a miss is cached too; a target that stopped being water forces a re-scan). Tests: `TestAmphibiousWaterReturn` in `tests/test_steering.py`
- `venom` gene: when a carrier's `jaw` bites another organism, a damage-over-time effect is applied to the victim (stored in `organism.venom_stacks`); damage per tick = `toxicity` × (1 − victim's `toxin_resistance`); `venom` also grants partial toxin resistance to the carrier; `toxin_gland` only poisons remains on death, `venom` actively poisons live prey
- `jaw` refuses to target organisms sharing the same `organism.name` (species label) as prey by default; the `cannibal` gene (checked via `organism.dna.genes`) lifts this restriction and adds extra aggression scaled by hunger
- `cannibal` also exploits kin's `pheromone` mating signal (`other.pheromone_strength`) to hunt weaker same-species kin from long range (`hunt_range`, default 160), well beyond `jaw`'s bite reach — the same broadcast meant to attract mates instead attracts a predator
- `fear` sets `organism.alarm_level` (0-1) whenever it directly spots a threat; other `fear`-carrying kin (same `organism.name`) within `alarm_range` (default 130) sense that alarm secondhand and flee the alarmed kin's position too, even without seeing the threat themselves — panic ripples through a herd faster than individual perception
- `asexual` gene: on a per-instance cooldown timer, if the carrier is of mating age (`Organism.is_of_mating_age()`) and has spare energy, it clones its own DNA (`DNA.clone()`, no crossover), mutates it at a boosted rate (`config.MUTATION_RATE * mutation_multiplier`), and spawns the child via `World.spawn_child_from_dna()` (which adds it, records the birth and the single parent uid) — no partner needed. Before spawning it checks `World.local_density()` against the same `config.MATING_DENSITY_RADIUS`/`MATING_DENSITY_LIMIT` used by sexual mating (fixed bug: it used to bypass this crowd-control check entirely, letting a single dominant `asexual` genotype cause runaway population avalanches); if blocked, the cooldown timer is left untouched so it retries every subsequent tick until the area thins out
- Random spawns (`World.spawn_organisms`: the starting population and `R`) draw the medium first, weighted by `World.water_share()` (water / (water + empty + heal) tiles), then a genome matched to it via `DNA.random_for(amphibious=...)` (re-rolls `DNA.random`, falling back to adding/stripping the gene); `Simulation.spawn_at` (LMB) matches the clicked tile. It used to be the other way round — the genome picked the medium, so only the ~30% of random genomes that roll `amphibious` went into the water whatever the lake area. Tests: `TestSpawnBalance` in `tests/test_world.py`, `TestRandomForMedium` in `tests/test_dna.py`
- `World.local_density(pos, radius, exclude=())` is the shared helper for counting nearby living organisms, used by both `World._try_mating()` and `AsexualGene.apply()`
- Genome length (via `DNA.mutate()`'s unbounded insertion/deletion random walk) can grow over generations, producing huge/long chain-like organisms; `Organism._build_body()` caps this by uniformly scaling down all body part offsets/sizes so the organism's `radius` never exceeds `config.MAX_ORGANISM_RADIUS`
- Genetics invariants (tests: `tests/test_genetics.py`): `DNA.crossover()` inherits the average gene copy count with an odd copy segregating at p=0.5 (the old `int(round(0.5)) == 0` dropped every gene carried by only one parent); shared genes are either copied whole or parameter-averaged (`Gene.blend()`, `config.CROSSOVER_BLEND_RATE`); `Gene.mutate()` uses additive steps scaled by `max(abs(default), config.MUTATION_STEP_FLOOR)` — no multiplicative downward drift and 0.0 is no longer absorbing. Optional `Gene.param_bounds` pins parameters whose semantics break outside a range (declared so far: `metabolism`, `regeneration`, `jaw.digestion`, `fat.storage`, `fat.reserve_factor`, `asexual.cooldown`/`energy_cost`/`mutation_multiplier` — unbounded, those reproduction limiters can mutate to zero, giving free every-tick cloning that bypasses the density check); angular parameters listed in `Gene.wrap_params` (`eye.direction`, `jaw.angle`) take pi-scaled mutation steps wrapped to [-pi, pi] (no clamping at the boundary) and blend via the circular mean, so angles near +-pi average to a near-backward child, not a forward one (exactly antipodal angles have no mean; `blend` keeps the first parent's angle instead of letting `atan2(0, 0)` fabricate a forward one). The same domain rules (bounds/sign/angle wrap) run in `Gene._constrain` at construction as well as mutation, so genomes loaded from disk or hand-written are sanitized. Genes must not override `Gene.mutate` — an old `EyeGene.mutate` override used to silently keep the pre-rework multiplicative logic and ignore `param_bounds`/`wrap_params`
- `Organism.upkeep` (idle energy/tick) scales with body mass (`config.MASS_UPKEEP_FACTOR`, `mass_ratio` vs `config.REFERENCE_BODY_MASS`) and genome length (`config.GENE_UPKEEP_COST`); the per-tick drain is `upkeep * organism.upkeep_efficiency`, where `upkeep_efficiency` resets to 1.0 each tick and each `metabolism` gene compounds `1.0 - efficiency` into it (so efficiency actually shapes the baseline drain); `fat` stores surplus into `organism.fat_reserve` (30% conversion loss) and only releases previously stored energy — it no longer generates energy from nothing; the reserve limit (`organism.fat_capacity`) is the largest `storage` across all fat genes (like `max_energy`), so mixed-storage carriers share one pool instead of truncating each other's deposits. The upkeep mass term is floored at 0 so an oversized `MASS_UPKEEP_FACTOR` override can't create free energy. Mass is measured from the unscaled body, so the `MAX_ORGANISM_RADIUS` cap shrinks an oversized organism's geometry without making its bulk free
- Movement cost is `config.ENERGY_COST_MOVE * (0.2 + 0.5 * speed/MAX_SPEED) * organism.mass_ratio` per tick in `leg` (heavy bodies pay proportionally more; a `MAX_SPEED` of 0 is degenerate config and costs only the base term instead of crashing); ambient food stream is governed by `config.FOOD_SPAWN_CHANCE`/`FOOD_MAX_ITEMS` and spawns items of energy `random.uniform(25, ENERGY_GAIN_FROM_FOOD)` — these knobs were previously hardwired/dead
- `eye`/`scent`/`touch` return early when their `range` parameter mutates down to <= 0: a range-less sensor is disabled (it still pays upkeep) instead of dividing by zero (`fear`/`cannibal` only divide for targets within `[1, range]`, so they are safe by construction)
- `metabolism.efficiency` is capped at 0.85 so at least 15% of the idle upkeep always remains; `fat.storage` is capped at 1.5 so energy buffers can't grow without limit; `fat.reserve_factor` is capped at 1.0 so hunger can always trigger mobilisation; `HEAL_ENERGY = 0.3` keeps heal-tile camping at a bounded multiple of upkeep instead of ~250x
- `regeneration` heals by draining `organism.fat_reserve` first; only the remainder falls back to an ambient trickle scaled by `efficiency` (the free-energy leak capped by `param_bounds` rate 0.5). Its part `count` is a real genome param (like `fat.count`/`leg.count`) so body-plan part counts heritably affect mass/upkeep — the old `random.uniform(1,4)` `_count` re-rolled on every clone; the expressed count now derives from the live parameter via `Gene.part_count`, so a mutated/blended `count` takes effect in the same organism rather than one generation late
- Body `side` (which side of the body a part sits on) is a heritable [0,1] genome parameter thresholded at 0.5 and expressed via `Gene.side` — same defect class as `part_count`: an `__init__`-time random `_side` re-rolled on every `clone()`, so children never matched their parents' layout. A sign-valued (+1/-1) parameter can't work because `_constrain` pins a non-negative default to >= 0. A gene created without an inherited `side` still randomises it so founders stay varied. All eight side-carrying genes (`eye`, `scent`, `fear`, `memory`, `venom`, `touch`, `toxin_gland`, `pheromone`) express it via `Gene.side`
- `Organism.parent_uids` (two uids for sexual, one for asexual, empty for founders) is logged as `parents` in `organisms.jsonl`, making a run's pedigree reconstructible offline
- On Wayland sessions, `main.py` defaults `SDL_VIDEODRIVER=wayland` (unless already set) to avoid an SDL/XWayland GLX probe crash (`BadValue ... X_GLXCreateContext`) seen with some NVIDIA/EGL driver setups

## Performance

- The most expensive simulation paths are: scent/eye scans, wall-circle collision checks, and spatial-grid queries.
- Key optimizations applied:
  - Tile map line-of-sight/hazard checks use an inline Bresenham walk instead of a generator.
  - `Touch` uses a single combined ray cast against the tile grid instead of world-unit sampling.
  - `Scent` and `Eye` compute squared distances first and only run line-of-sight checks for targets that can beat the current best score.
  - `Organism` caches nearby organisms per tick and stores immutable genome-derived counts.
  - `Renderer` caches a fully static map background (animated tiles are excluded via `draw_tiles(skip_tiles=...)`) and only redraws pulsing tiles (`ANIMATED_TILES` in `render/tile_drawing.py`) each frame, using rectangles pre-merged horizontally and vertically in `Renderer._rebuild_animated_tile_rects` (tile layout is static between cache rebuilds). The map blit covers the whole screen, so `render()` skips the redundant screen-wide background fill.
  - Body parts are sorted once in `Organism._build_body` instead of every frame.
- Repeatable performance smoke test:
  - `uv run python -m unittest tests.test_performance`
- Verification commands:
  - `uv run python -m compileall src`
  - `uv run python -m unittest discover tests`
  - `SDL_VIDEODRIVER=dummy timeout 10 uv run wee-life2`
  - `SDL_VIDEODRIVER=dummy timeout 5 uv run wee-life2 --edit-map`
  - Textual editor headless tests are in `tests/test_config_editor.py`; the editor can also be opened manually with `uv run wee-life2 --edit-config`

## Architecture

- Uses `uv` for dependency management and virtual environment.
- Entry point: `wee_life2/main.py`.
- External dependencies: Pygame (simulation/editor rendering), Textual (config editor TUI), textual-slider (sliders in the config editor).
- Genes are registered in `wee_life2/genes/__init__.py:GENE_REGISTRY`.
- Body parts are assembled from `BodyPartBlueprint` objects returned by each gene.
- Simulation loop is in `wee_life2/simulation.py`.
